# Repository audit — 2026-09-07

Baseline: `52e26b0` on `main`. Scope: registry discovery and refresh,
installation lifecycle, local HTTP API, client management UI, packaging,
documentation, dependencies, and GitHub workflow configuration.

## Findings and fixes

| Priority | Finding | Resolution and evidence |
| --- | --- | --- |
| P1 | Scheduled refresh pushes directly to protected `main`; the last eight runs failed. | Publish to one bot PR, preserve branch protection, and use the normal PR checks after GitHub's required workflow approval. A temporary bare Git repository with a hook rejecting pushes to `main` verifies first creation, repeat update, and unchanged runs. |
| P1 | Restart can interrupt a concurrent profile mutation, and helper launch errors are reported after HTTP success. | Serialize mutations/restart requests; acknowledge helper launch before responding; preserve the running host and permit retry after launch failure. HTTP regression tests cover concurrent requests. |
| P1 | Discovery, preview, and artifact inspection disagree on valid manifests and Node export precedence. | Share manifest/path validation, honor `exports` before `main`, support nested Node import conditions, reject unsafe artifact and repository paths, and reject duplicate catalog IDs. |
| P1 | Registry builder writes data without checking the runtime schema; transient lookup failures silently remove entries. | Validate the whole snapshot and publish atomically. Invalid/missing manifests are excluded; transport failures abort publication. Offline subprocess tests verify last-good preservation and timestamp-only no-ops. |
| P2 | Hung or excessive-output subprocesses can hold the profile lock indefinitely; early rejection can race rollback. | Bound execution/output, terminate the process group, and wait for child closure before returning failure. |
| P2 | Delisted plugins vanish from the installed UI; install blocks also hide removal controls. | Render installed entries independently of catalog membership. Keep disable/uninstall available and include managed records absent from profile dependencies. |
| P2 | Preview failures permanently disable an install button for the session; aliases can use the wrong managed ID. | Allow retry and route lifecycle actions through the installed record ID. |
| P2 | Mutation origin checks compare authority without scheme; JSON prefix checks accept lookalike media types. | Compare the complete serialized origin with the actual connection protocol and accept the exact JSON media type. |
| P2 | Inherited object properties look like installed packages; duplicate dependency roles appear active. | Use own-property checks, flag contradictory roles, require an exact preview, prevent duplicate managed IDs, and permit stale absent records to be removed. |
| P2 | Stale online snapshots report a live update; stop during a request can revive scheduling metadata. | Preserve last-good source status, report stale data accurately, and schedule only while running. |
| P2 | README installs released 0.5.0 while describing 0.6.x behavior. | Distinguish the stable release and development line and provide a source-build installation path. |

## Remote rollout requirement

The repository currently disallows GitHub Actions-created PRs. Before enabling
this publication flow, enable the repository's **Allow GitHub Actions to create
and approve pull requests** setting; default token permission remains read-only.
The workflow neither approves nor merges its own PR. Merge the code repair after
required CI passes, then manually run `Refresh registry` to verify actual PR
creation, approval of the normal PR checks, and the resulting reviewed catalog update.

## Boundaries

- Supported runtime remains exactly DSH `0.1.0-rc.6`; this audit does not claim
  compatibility with newer DSH releases.
- Existing released tarballs are immutable and remain at 0.5.0. Source fixes
  do not update an already-installed copy automatically.
- Profile locks fail closed after an unclean process termination. An orphaned
  lock may require operator cleanup after confirming its owner is no longer
  running; this audit does not introduce unsafe automatic lock stealing.

## Live publication follow-up

PR #12 merged after Linux/macOS Node 22 CI and dependency review passed. The
Actions PR-creation setting is enabled with default token permissions kept at
read-only. Manual refresh run `34086167440` completed successfully, created
PR #13, and explicitly dispatched all three required CI checks successfully.

Reviewing that generated diff exposed a further data-quality defect: GitHub's
1,000-result search window dropped previously admitted, still-valid plugins.
The follow-up revalidates historical install locations and retains those still
passing admission. A subprocess regression test covers disappearance from the
search window. The incomplete PR #13 snapshot must be regenerated using this
fix before merging.


The live follow-up also showed that a successful branch-only dispatch does not
satisfy this repository's checks on the PR test-merge commit. The final flow
therefore uses GitHub's normal `pull_request` checks: a maintainer approves the
bot-triggered workflow, then merges after it passes. The extra branch dispatch
and registry-only path exclusion were removed. No protection rule is bypassed.

License assessment now withholds the open-source bonus from proprietary and
unrecognized declarations; one additional regression test covers that boundary.
